# 安卓端的上下文管理

本文对应 FoliKeep 1.1.0。这里的 harness 是阅读问答的执行层，不是单独的模型，也不是可以操作手机或运行任意工具的通用 agent。

## 分工

`core:model/ConversationHarness.kt` 负责 token 估算、逻辑历史、摘要指纹、压缩边界和费用计算，代码不依赖 Android UI。`feature:conversation/ConversationViewModel.kt` 把这些规则与本地存储、发送和流式显示连起来。`core:ai/OpenAiCompatibleProvider.kt` 构造实际 HTTP 请求。

这些工作在安卓应用里执行。模型推理、生成摘要及服务商的 KV 缓存不在手机上执行。模型返回的思考文本也不能代替执行层的规则。

## 一段问答对应一组资料

最初的选区是这段问答的根来源。补充选区通过 `conversationAnchorId` 指向它，消息里的 `sourceAnchorId` 指向具体资料。多个标注可以打开同一个对话，但不同对话不会自动交换历史。

文字资料保留原文快照；图片资料保留本地局部图片。补充文字或图片会产生一条 `role=source` 的本地记录，发送时转换成用户资料消息，附在当时的时间位置。它不算一轮提问。

未压缩时，实际请求顺序是：

```text
system: 固定阅读助手提示词
user: 最初资料来源（文字或图片）
user / assistant: 已有问答
user: 在此时补充的资料（可以含图片）
user / assistant: 后续问答
user: 当前问题（可以含回答中的引用）
```

正常追问只在后面追加。原图和补充图都待在各自的来源消息里，每轮重新携带有效图片；没有图像摘要替代和按需取图 tool。补充图片缺失会报错，不会悄悄当作纯文字发出。

## 本地记忆与本次上下文

本地数据库保存完整聊天、原始资料、摘要和用量账本，知识卡片保存用户选择的内容。关闭窗口或重开应用不会靠模型去“记住”这些内容。

一次 API 请求只包含本段问答的有效资料、逻辑历史或旧历史摘要以及本次问题。卡片不是自动检索记忆；其他书、其他问答的内容也不会自动加入。

失败、停止或截断的回答可以保留在历史中，但会带“未完成”的提示。重试在请求里使用逻辑回答版本，不把同一个问题的所有重试答案都堆进去。模型的可见思考文本按设置可保存在本地，后续上下文不发送它。

引用旧回答时，当前发送逻辑带的是用户选中的引用快照；不能因此假定整个旧回答或邻近教材段落也已发送。

## 预算与压缩何时触发

默认值是模型上下文容量 65,536、输入预算 32,768、回答上限 8,192、每张图片预算 8,192 token。它们是应用配置，并不代表某个服务商的真实模型容量，使用前应按模型调整。

有效输入上限：

```text
min(用户输入预算, 模型上下文容量 - 本次回答上限 - 2048 安全余量)
```

文字估算按 ASCII / 非 ASCII 字符分别计算，再加 15% 余量与消息开销，不是精确 tokenizer。图片按不同来源资产数乘图片预算预留，服务商的真实图像计费可能不同。

每次发送时先检查：原始资料、全部有效补充资料、最近 4 轮逻辑问答、当前问题是否已经超过输入上限。如果这部分都放不下，直接提示用户调整，**不会先调用付费摘要**。

能放下时再估算完整上下文。超过预算才整理更早的完整问答，不是先把正式请求发出去，等超限再做摘要。

一次发送最多调用 3 次摘要。单块尽量控制在有效输入预算的 2/3 内；不能拆开一个问题与它的回答。摘要关闭思考，输出上限 1,024 token。一个早期完整轮次大到无法装进摘要块时，可能无法压缩，最终明确报错。

摘要完成后重新估算。仍然超限就停止发送，提示移除资料、提高输入预算 / 模型容量或降低回答上限。安全余量不能保证实际 tokenizer 永不超限；模型接口仍可能拒绝请求，应用保留问题及已收到内容，不进行无限自动重试。

## 摘要如何复用

摘要记录根来源的 hash、已覆盖的最后一条消息 ID、已覆盖历史的 hash、文本和模型字段。复用时核对来源、覆盖位置及历史指纹，并且不允许侵入当前受保护的最近 4 轮。

摘要字段保存了生成模型，但当前有效性检查不会仅因切换模型而作废。摘要本身只是文本；切换模型仍可能改变 API 缓存行为。

摘要不删除本地历史。已被摘要覆盖的补充资料会从历史里取出来，以原文 / 原图放在摘要前，然后附上摘要和未压缩历史：

```text
system: 固定提示词
user: 最初来源
user: 被压缩范围内的补充资料，原样保留
user: 旧历史摘要，明确标记不是教材原文
user / assistant / source: 未压缩历史
user: 当前问题
```

因此压缩会改变请求中部；它不是保持所有旧前缀不变的机制。这里优先保证资料可追溯和输入有界。

## 缓存策略

不在应用里建立模型 KV 缓存，也不把 API 回答缓存当成新的模型回答。应用维护稳定的提示词和来源，正常追问按时间追加，避免每轮改写前面的内容。相同 JSON 文本 / 消息顺序只是前缀稳定的工程条件，实际命中由模型服务处理。

[DeepSeek 官方说明](https://api-docs.deepseek.com/news/news0802/)指出，缓存按从输入开头开始的相同前缀匹配，输入中间相同的段落不能单独据此命中。不要引用这篇旧公告的历史单价当作当前定价。

可能损失可复用前缀的操作包括：更新系统提示词、压缩或重写摘要、移除来源、切换模型 / 服务商。即使输入未变化，服务商缓存过期也可能不命中。图片缓存与思考相关历史的规则另看服务商，当前客户端没有统一保障。

解析的用量字段包括 `prompt_tokens` / `input_tokens`、`prompt_cache_hit_tokens` / `cached_tokens` / `prompt_tokens_details.cached_tokens`、输出和思考 token。接口没返回就是未知。

已知输入与缓存字段时，可以计算单次输入命中率 `cached / input`。统计多次时应使用 `sum(cached) / sum(input)`，不要平均每轮百分比；缺少用量的调用应单列。当前界面展示 token 计数，没有统一的全局命中率报表。

## 费用限制的边界

价格由用户配置，回答与摘要均记录用量。估算时按无缓存输入预留，思考不另加到已包含它的输出上。未知单价或缺少用量无法给出准确金额；本机每日账本也不包括同一 API Key 在别的软件里使用的费用。

停止或断流可能已经计费。缺少用量的记录标“费用待确认”，不能当作免费。每日累计目前只使用已有费用估算，所以它是辅助预算，不能代替服务商账户级限额。

## 资料不足、移除与已知缺点

提示词要求模型指出缺少的定义、条件或依据，请用户补充；这只是模型行为要求，不能保证它每次都正确判断。应用不自动 OCR、读取邻页或检索全书。

移除 AI 资料后，下次发送不再携带该原文 / 图片，也移除页面标记。旧回答、卡片和本地原始数据保留，旧回答仍可能引用已经移除的资料；摘要若在受覆盖历史中包含它，会因指纹变化失效。不要把“移除资料”理解成消除所有旧回答中的信息。

仅移除页面标注不等于从 AI 上下文移除资料。补充标注删除不删除整段原问答；根标注连问答删除时，整组入口隐藏。详见[数据说明](privacy.md)。

当前没有通用工具调用循环、跨书检索记忆、用户模板、自动复习计划。上下文保存得完整也不代表教材依据足够，两者需要分开处理。

## 验证入口

- `ConversationMemoryTest`：逻辑历史、保留近期轮次、压缩块边界、摘要指纹与资料保留。
- `MultiSourceRequestTest`：补充图片的消息位置、已有消息前缀、估算提示词与实际请求一致、缺图报错。
- `GenerationOptionsTest` / `ChatSseTest`：思考与输出参数、流式用量和结束原因。
- `verify-source-sql.py`：共享问答、检索去重、移除、删除 / 撤销、10→11 迁移。
- `SharedSourcesIntegrationTest` / `SupplementMigrationTest`：需要 Android 设备或模拟器执行。
