# FoliKeep

<img src="docs/images/icon.png" width="96" alt="FoliKeep 图标">

一个安卓 PDF 阅读器，可以对选中的文字或圈出的图片提问，把问答留在对应的页面上。

做这个项目的原因很简单：看课件时遇到不懂的公式，通常要截图、切到聊天软件，再把问题说一遍。解释看完就散在聊天记录里，下次复习还得找。FoliKeep 把阅读、提问和保存回答放到一起。资料和记录存在本机，AI 接口由自己配置。

主要在安卓平板上使用，也有手机窄屏布局。需要 Android 8.0 或以上；当前版本是 **1.1.0**。

## 怎么用

### 导入资料

在书架点「导入资料」，选择 PDF 或图片。文件会复制到应用的私有目录，移动原文件不影响继续阅读。应用会记住阅读位置。

PPT / PPTX 需要先转成 PDF。有文字层的 PDF 可以选字；扫描版 PDF 用圈图提问，目前没有 OCR。

安装包在 [Releases](https://github.com/TINSR/FoliKeep/releases/latest) 下载。自行构建的方法见[开发说明](yuejian/README.md)。

### 配置 AI

打开「模型设置」，填写服务商的 **Base URL、API Key、文字模型 ID**。Base URL 不要带 `/chat/completions`，也不要把密钥放进地址里。

圈图提问还需要启用图片能力，并填写支持图片输入的模型 ID。接口使用 OpenAI 兼容的 Chat Completions 协议；DeepSeek 和小米 MiMo 有思考开关适配，其他服务能否正常使用取决于接口兼容性。文字模型和图片模型可以不同。

首次发送或资料范围变化时，应用会显示确认窗口。连接测试也是一次模型调用，可能计费。

### 阅读、提问、留笔记

1. 长按并拖选文字，选择高亮或「问 AI」。图片、图表和扫描页可以拖出矩形选区后提问。
2. 回答在问答区逐步显示，可以停止、继续追问，也可以选中回答中的一段再问。
3. 点页面上的高亮或圈框，可以回到对应问答。文字高亮和圈框重叠时，优先打开文字高亮。
4. 答案下面的「存为卡片」可以把问题和回答一起保存，也可以只摘取回答的一部分。
5. 卡片集合可以切换全书 / 本页，点开查看、定位原文、编辑、排序或删除。详情正文支持缩放。

如果解释缺少依据，比如符号定义在前一页，点「补充资料」，翻页选择相关文字或圈图，再点「添加到当前问答」。这些资料属于同一个窗口；点任意关联标记，都能回到这段对话。添加资料不会自动发送，点「继续回答」后才调用 AI。

标注颜色、黑白主题、回答字号都可以调整。删除标注和移除 AI 资料是两件事，具体区别见[隐私与数据说明](docs/privacy.md)。卸载前请导出备份；备份不包含 API Key。

## 追问时，AI 会收到什么

这里的 harness 指应用里管理一次问答的代码：组装资料和历史、检查输入与费用预算、压缩旧对话、处理流式响应，再把结果保存。它运行在安卓端；模型推理仍由配置的服务商完成。

每段问答有自己的资料和历史，不会把全书问答混在一起。普通追问大致发送：

```text
阅读助手提示词
最初选中的文字或局部图片
已有问答、按时间加入的补充资料
本次问题
```

上下文快满时，应用在发送正式回答请求前整理较早的对话，保留最近 **4 轮**问答。补充资料不算问答轮次，原文和原图不会被摘要替代。本地完整记录也不会因为压缩而删除。

如果「资料 + 最近 4 轮 + 当前问题」本身就超出预算，会先拦截，不先花钱做无用的摘要。可以移除资料、调整输入容量或降低回答上限。更详细的触发条件、摘要复用和边界行为见 [上下文管理](docs/harness.md)。

**图片目前会随追问再次发送。** 还没有实现“只发一次图片，之后让 AI 按需取图”的工具。AI 也不能自行翻页找资料；提示词会要求它指出缺少什么，补充由用户完成。

## 缓存命中与费用

应用没有自己的模型 KV 缓存。它做的是尽量保留请求里重复的前缀：固定提示词、固定来源，正常追问往后追加记录；新增图片留在对应的资料消息里，不搬到最新问题旁边。

这样有利于服务商复用已有输入。例如 DeepSeek 的缓存按相同前缀匹配，普通多轮对话可以复用此前内容。[DeepSeek 官方说明](https://api-docs.deepseek.com/news/news0802/)

压缩历史、移除资料、改变提示词或切换模型，都可能改变可复用范围。服务商也会清理缓存。**这个项目不保证某个命中率，更没有“97% 命中”的内置承诺。** 图片缓存规则也要看服务商，不能从文字缓存推断。

「本次用量」显示服务商返回的输入、缓存命中、输出和思考 token。缺少字段会显示未知。费用用设置里的单价估算；摘要调用也入账。思考 token 通常已包含在输出 token 中，不会再重复加算一次。金额以服务商账单为准，应用的预算限制只覆盖本机已记录的调用。

## 数据存在哪里

文件副本、阅读位置、标注、对话、摘要和卡片保存在本机。没有账号系统、资料云同步或分析 SDK。API Key 使用 Android Keystore 加密保存。

使用 AI 时，所选资料和当前问答上下文会发送到你配置的接口，所以“本地保存”不等于“AI 离线运行”。仅阅读和查看已有问答不需要调用模型。详见[隐私说明](docs/privacy.md)。

## 开发

原生 Kotlin / Jetpack Compose，使用 Room、DataStore、Hilt、协程和 OkHttp。PDF 显示使用系统 PdfRenderer，文字坐标提取使用 PDFBox-Android；回答用本地 Markdown 和 KaTeX 渲染。

```text
yuejian/
  app/                  应用入口与依赖注入
  core/model/           数据接口、预算估算与对话压缩规则
  core/ai/              模型接口、流式解析与密钥存储
  core/database/        Room 数据库、迁移与 schema
  core/files/           文件、标注、问答、卡片和备份
  core/pdf/             PDF 渲染、文字层与圈图
  core/markdown/        回答与公式排版
  feature/              书架、阅读、问答与设置界面
docs/                   使用、架构与发布说明
```

`yuejian` 目录和 `com.yuejian.*` 是早期工程名，暂时保留，避免影响包名、升级及已有数据。对外名称是 FoliKeep。

构建和测试命令见 [yuejian/README.md](yuejian/README.md)。想改上下文逻辑，从 `ConversationHarness.kt`、`ConversationViewModel.kt` 和 `OpenAiCompatibleProvider.kt` 看起即可。

## 当前限制

- 只支持本地 PDF 和图片，没有 PPT 解析、OCR、整书检索或云同步。
- 没有长期跨书记忆，也没有自动检索教材、自动操作手机或通用工具执行循环。
- PDF 文字层的提取质量取决于文件；复杂排版可能有顺序错乱或字符缺失，圈图通常更合适。
- token 估算不是服务商的精确 tokenizer，图片预算按每张保守预留。
- 预算不是服务商账户的硬限额，中断且未返回用量的调用无法确定费用。
